# Настройка облака (Supabase)

Облако нужно, чтобы профиль ученика со всеми тренировками (каждый ответ и каждая подсказка)
сохранялся в интернете, открывался на другом компьютере (а потом на iPhone) и был виден в админке.
Пока облако не настроено, программа работает как раньше, полностью локально: кнопок облака просто не видно.

Схема базы — [`DATABASE.md`](DATABASE.md), как это устроено в программе — раздел «Облако» в
[`ARCHITECTURE.md`](ARCHITECTURE.md).

> Облако общее для десктопа (заморожен) и веб-версии [`WEB.md`](WEB.md): один и тот же проект
> Supabase, один профиль на почту. Шаги 1–3 ниже (проект, таблицы, письма) нужны всем клиентам,
> шаг 4 — только десктопу.

> Названия пунктов в панели Supabase иногда меняются. Если пункт называется немного иначе,
> ищи по смыслу.

---

## 1. Создать проект (один раз, бесплатно)

1. Открой https://supabase.com → **Start your project** → войди через GitHub или почту.
2. **New project**:
   - *Name:* `nmt-tutor`;
   - *Database Password:* придумай и **сохрани** (понадобится только для прямого доступа к базе);
   - *Region:* **Central EU (Frankfurt)** — ближе всего к Украине;
   - *Plan:* Free.
3. Подожди 1–2 минуты, пока проект создаётся.

> Бесплатный проект **засыпает после 7 дней без запросов**. Разбудить: зайти в панель и нажать
> **Restore project**. Пока ученики пользуются программой, он не уснёт.

## 2. Создать таблицы

1. Слева **SQL Editor** → **New query**.
2. Скопируй туда весь файл [`supabase/migrations/20261118000000_cloud_sync.sql`](../supabase/migrations/20261118000000_cloud_sync.sql).
3. Нажми **Run**. Должно появиться *Success. No rows returned*. Если Supabase спросит про
   «destructive operations» (в скрипте есть `drop policy if exists` / `drop trigger if exists`) —
   подтверждай: скрипт пересоздаёт только свои правила, данные не трогает.

Скрипт можно запускать повторно — он ничего не сломает. Проверить в **Table Editor**: `profiles`,
`profile_meta`, `sessions`, `session_subjects`, `session_answers`, `hint_events`, `profile_subject_stats`,
`app_settings`, `products`, `purchases`, `entitlements`, `session_credits`, `admins`.

Для веб-версии так же запусти [`supabase/migrations/20261120000000_access_gate.sql`](../supabase/migrations/20261120000000_access_gate.sql)
(закрытый доступ по логину и паролю) и добавь первый логин:
`select public.set_gate_login('логин', 'пароль');` — подробнее в [`WEB.md`](WEB.md#закрытый-доступ-логин-и-пароль).

## 3. Вход по коду из почты

Программа входит без пароля: ученик вводит почту, получает 6-значный код и вводит его.

1. **Authentication → Sign In / Providers → Email**: включено (*Enable Email provider*).
   Там же *Email OTP Length* = **6**, *Email OTP Expiration* = **3600** (час).
2. **Authentication → Emails → Templates**. По умолчанию письма содержат ссылку, а нам нужен код.
   В двух шаблонах — **Confirm signup** (первый вход новой почты) и **Magic Link** (следующие
   входы) — замени текст письма, например, на:

   ```html
   <h2>Код для входу в НМТ Сова-Репетитор</h2>
   <p>Твій код: <strong style="font-size:24px">{{ .Token }}</strong></p>
   <p>Код діє 1 годину. Якщо ти не входив(ла) у програму — просто проігноруй цей лист.</p>
   ```

   Тему письма можно поставить «Код для входу в НМТ Сова-Репетитор».

### Почта для настоящих учеников (обязательно перед запуском)

Встроенная почта Supabase — только для проверки: она шлёт **несколько писем в час** и только на
адреса участников твоей команды в Supabase. Для учеников нужен свой SMTP, бесплатные варианты:
**Resend** (3 000 писем в месяц), **Brevo** (300 писем в день).

**Project Settings → Authentication → SMTP Settings** → *Enable Custom SMTP* → данные из
выбранного сервиса (хост, порт, логин, пароль, адрес отправителя). После этого в
**Authentication → Rate Limits** можно поднять лимит писем в час.

## 4. Подключить программу к проекту

1. **Project Settings → API Keys** (или **Data API**): скопируй
   - **Project URL** — вида `https://abcdefgh.supabase.co`;
   - **Publishable key** (`sb_publishable_…`). В старых проектах он называется **anon public**.
2. Создай файл `nmt_tutor/cloud_config.json` (образец — `nmt_tutor/cloud_config.example.json`):

   ```json
   {
     "supabase_url": "https://abcdefgh.supabase.co",
     "supabase_key": "sb_publishable_xxxxxxxx"
   }
   ```

3. Перезапусти программу. В кабинете появится строка «☁️ Зберігати в хмарі — підключити».

> ⚠️ Publishable / anon ключ **публичный**: его можно класть в программу и в git, защиту данных
> обеспечивают правила доступа (RLS) в базе. **Secret / service_role** ключ не клади никуда,
> кроме будущего сервера: он обходит все правила.

Для разработки вместо файла можно задать переменные окружения `NMT_SUPABASE_URL` и `NMT_SUPABASE_KEY`.
Сборка Windows (GitHub Actions) берёт `cloud_config.json` автоматически, если он есть в репозитории.

## 5. Как пользоваться

- **Подключить профиль:** кабинет → строка «☁️ Зберігати в хмарі — підключити» (или меню
  **Профіль → ☁️ Зберігати в хмарі…**) → почта → код из письма. Все прошлые тренировки сразу загрузятся.
- **Начать тренировку** профиль с облаком может только **с интернетом**: сервер записывает старт (а с
  покупками будет проверять лимит). Без интернета программа так и скажет.
- **Дальше всё само:** после каждой тренировки (со всеми ответами и подсказками) и правки профиля
  программа в фоне отправляет изменения и забирает новое. Если интернет пропал на финише, тренировка
  лежит на компьютере и уйдёт при следующей синхронизации. В кабинете видно:
  «🔥 3 дні поспіль • ☁️ почта • збережено в хмарі 14:05». Нажатие на эту строку — синхронизировать сейчас.
- **Другой компьютер:** «Хто займається?» → **☁️ Увійти через пошту** (а если профилей ещё нет —
  ссылка «Вже маєш профіль у хмарі?» под формой) → почта → код. Профиль скачается со всей историей.
  PIN-код в облако не отправляется: на новом компьютере его можно задать заново в «Мій профіль».
- **Одна почта — один профиль.** Для второго ученика нужна своя почта.
- **Профіль → ☁️ Вийти з хмари на цьому комп’ютері** — отключить облако только здесь; данные
  остаются и тут, и в облаке.
- **Профіль → ☁️ Видалити дані з хмари…** — удалить аккаунт и все его данные из облака (этого
  требует App Store). На компьютере данные остаются.
- **Удаление профиля** на компьютере облако не трогает: профиль можно снова скачать по почте.

## 6. Админ (для будущей админки)

Админ видит **все** профили и результаты (только чтение), ученики — только свои.

1. Войди в программу своей почтой (или создай пользователя в **Authentication → Users → Add user**).
2. **Authentication → Users** → скопируй его **UID**.
3. **Table Editor → admins → Insert row** → `user_id` = этот UID → Save.

Статистику уже можно смотреть в **SQL Editor** (там запросы идут с правами владельца и видят всё):

```sql
-- ученики: сколько тренируются, уровень, серия дней
select * from admin_students order by last_session_at desc nulls last;

-- самые трудные темы
select * from admin_sections where answers >= 10 order by correct_pct limit 20;

-- средний балл по предметам
select subject, count(*) as sessions, round(avg(nmt_200), 1) as avg_nmt
from session_subjects ss join sessions s on s.id = ss.session_id
where not s.mistake_drill and ss.nmt_200 is not null
group by subject order by sessions desc;
```

## 7. Проверка без Supabase (для разработчика)

`python tests/cloud_integration_test.py` поднимает в Docker настоящие PostgreSQL и PostgREST
(из них и состоит Supabase), применяет миграцию и проверяет старт и сдачу тренировок с ответами и
подсказками, статистику и серию дней, синхронизацию двух «компьютеров», запрет прямой записи,
изоляцию аккаунтов, доступ админа, анонимный доступ и удаление аккаунта. На GitHub этот тест
запускается автоматически (job `cloud-schema`).

## Приватность

Политика конфиденциальности — [`site/privacy/index.html`](../site/privacy/index.html), публикуется на
GitHub Pages: https://aldroid007.github.io/NMT_Ow/privacy/ (адрес — `PRIVACY_URL` в `nmt_tutor/config.py`).

- Окно входа по почте отправляет код только после галочки «Я погоджуюсь з Політикою конфіденційності»;
  ссылка в окне и пункт **Довідка → Політика конфіденційності** открывают страницу в браузере.
- В облаке хранятся: имя, аватар, предметы, цели, дата НМТ, почта (в Supabase Auth), тренировки с каждым
  ответом и подсказкой. Текстовые отчёты, свои банки и PIN остаются на компьютере.
- Если меняется состав данных (например, покупки), обнови текст и дату редакции в политике.

**Публикация (один раз):** GitHub → репозиторий → **Settings → Pages → Source: GitHub Actions**. Дальше
workflow `Publish site` выкладывает папку `site/` при каждом пуше в `main` (или вручную: Actions →
Publish site → Run workflow).
