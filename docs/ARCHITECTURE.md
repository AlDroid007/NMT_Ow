# Архитектура «НМТ Тренажёр • Сова-Лиза»

Проект — Python-пакет `nmt_tutor` и файл запуска рядом с ним. Пакет разделён на три слоя:
**ядро**, **хранилище данных** и **интерфейс**. Ядро не знает ни про окна, ни про файлы,
поэтому к нему можно подключить другой интерфейс (например, iOS через BeeWare) без переделки логики.

Как запускать на другом компьютере — см. [`ИНСТРУКЦИЯ_ЗАПУСКА.md`](../ИНСТРУКЦИЯ_ЗАПУСКА.md).

## Структура

```
nmt_tutor_mac.py          ← запуск двойным кликом (≈30 строк, просто вызывает app.main)
nmt_tutor/
├── app.py                ← точка входа: GUI / --cli / --selftest, открытие хранилища
├── ЯДРО (без tkinter и без работы с файлами)
│   ├── config.py         ← предметы, их настройки, шкалы перевода в 100–200
│   ├── data/             ← база заданий (189 шт., JSON), загружается при первом обращении
│   ├── generators/       ← 40 генераторов заданий, по модулю на предмет, подгружаются по требованию
│   ├── engine.py         ← проверка ответов, план сессии, баллы, работа над ошибками, текст отчёта
│   ├── hints.py          ← 10 уровней подсказок Совы-Лизы
│   ├── banks.py          ← проверка и слияние своих банков заданий (.json)
│   ├── cli.py            ← консольный режим
│   └── selftest.py       ← самопроверка без окон (для CI и собранного exe)
├── storage/              ← ХРАНИЛИЩЕ: единственное место, которое трогает диск
│   ├── base.py           ← интерфейс Repository (результаты, отчёты, банки, прогресс)
│   ├── sqlite_repo.py    ← основная реализация: SQLite, каждая запись зашифрована
│   ├── memory_repo.py    ← в памяти (тесты и работа «без сохранения»)
│   ├── crypto.py         ← AES-256-GCM (пакет cryptography)
│   ├── keystore.py       ← ключ: Связка ключей macOS / DPAPI Windows / файл
│   ├── legacy_import.py  ← разовый перенос старых .json и отчётов в базу
│   ├── paths.py, files.py
│   └── __init__.py       ← open_repository(): открыть, проверить ключ, мигрировать
└── ui_tk/                ← ИНТЕРФЕЙС на Tkinter
    ├── app.py            ← главное окно, меню, таймер, ярлык Windows
    ├── screens/          ← экраны: setup (выбор), session (тест), drill (ошибки), results
    ├── widgets.py        ← скруглённые кнопки, карточки, плитки предметов, варианты ответа
    ├── scroll.py         ← плавная прокрутка (трекпад Tk 8/9, колесо мыши)
    ├── owl.py            ← анимированная сова
    └── theme.py          ← цвета, шрифты, рисование скруглений

tests/smoke_test.py       ← самопроверка + короткий прогон окна
packaging/nmt_tutor.spec  ← сборка PyInstaller (папка с exe, Python внутри)
packaging/windows/        ← ПРОЧИТАЙ_МЕНЯ.txt, кладётся в Windows-сборку
.github/workflows/build-windows.yml ← сборка и тест Windows-версии на GitHub
```

## Правила слоёв

- **Ядро** (`config`, `data`, `generators`, `engine`, `hints`, `banks`) не импортирует `tkinter`
  и не читает/пишет файлы пользователя. Импортируется без окон за ~20–40 мс.
- **Хранилище** (`storage/`) — единственный слой, который знает пути на диске. Остальной код
  работает только через интерфейс `Repository`.
- **Интерфейс** (`ui_tk/`) получает задания и проверку от ядра, а сохраняет через `Repository`.
  Сам ничего не считает и не пишет на диск (кроме «Сохранить отчёт (.txt)» по выбору пользователя).

## Как это работает вместе

1. **Запуск.** `nmt_tutor_mac.py` → `app.main()` открывает зашифрованное хранилище и создаёт окно
   `NmtTutorApp`. Нет пакета `cryptography` — программа предлагает работать без сохранения
   (`MemoryRepository`).
2. **Сессия.** Интерфейс берёт план у ядра (`engine.build_session_plan`), проверяет ответы через
   `engine.evaluate_answer`, подсказки получает из `hints.build_10_hints`.
3. **Сохранение.** Результат уходит в хранилище (`repo.save_result`), шифруется и записывается в
   `~/Documents/NMT_Tutor/nmt_tutor_data.sqlite3`.
4. **Ключ шифрования** лежит не рядом с базой, а в системном хранилище: Связка ключей на Mac
   (запись `NMT_Tutor`), DPAPI на Windows (файл `.nmt_tutor_key`). Если ключ не подходит, база не
   удаляется, а переименовывается в `.unreadable-…`, и создаётся новая.

## Хранение данных

- Таблицы `meta`, `results`, `reports`, `custom_banks`; содержимое каждой записи — зашифрованный
  JSON (версия + nonce + шифротекст, AAD = имя таблицы).
- Версия схемы — `PRAGMA user_version`, миграции в `sqlite_repo.MIGRATIONS`.
- Папку данных можно переопределить переменной окружения `NMT_TUTOR_DATA_DIR`.
- При первом запуске старые файлы (`*.json`, `nmt_report_*.txt`) из папки данных копируются в базу;
  сами файлы не трогаются.

## Режимы запуска

| Команда | Что делает |
|---|---|
| `nmt_tutor_mac.py` | Окно программы (Tkinter) |
| `nmt_tutor_mac.py --cli` | Консольный режим, без окон и без сохранения |
| `nmt_tutor_mac.py --selftest [--out FILE] [--real-keystore]` | Самопроверка ядра и хранилища, код выхода 0/1 |
| `python tests/smoke_test.py [--no-gui]` | Самопроверка + прогон окна |

## Сборка Windows

GitHub Actions (`build-windows.yml`) при пуше в `develop`/`main` или вручную:
ставит Python 3.13, прогоняет `tests/smoke_test.py --real-keystore` (проверка DPAPI),
собирает `packaging/nmt_tutor.spec`, запускает собранный exe с `--selftest` и выкладывает
архив **NMT_Sova_Tutor_Windows** (Actions → Build Windows app → Artifacts).

В spec модули пакета перечисляются по файлам (`hiddenimports`), потому что генераторы
импортируются по имени во время работы и PyInstaller сам их не находит.

## Как расширять

- **Новый генератор** — функция в `generators/<предмет>.py`, зарегистрировать ключ в
  `generators/__init__.py` (`SUBJECT_GENERATORS`). `selftest` проверит, что генератор принимает
  собственный ответ и даёт 10 подсказок.
- **Новый интерфейс** (iOS, веб) — переиспользует ядро и `storage` целиком, переписывается только
  аналог `ui_tk`.
- **Облачная синхронизация** — ещё одна реализация `Repository` (`storage/base.py`); интерфейс не
  меняется.
