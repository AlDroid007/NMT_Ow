# Веб-версия (и будущее iOS-приложение)

> Статус: код готов и проверен на реальном проекте Supabase; публикация на Cloudflare Pages — по инструкции ниже.

Главный клиент НМТ Сова-Репетитор: веб-приложение в папке `web/`. Им удобно пользоваться и
тестировать с любого устройства, а через **Capacitor** тот же код собирается в приложение для iPhone
и публикуется в App Store. План — [`ROADMAP.md`](ROADMAP.md), этапы 2 и 3.

## Стек

| | |
|---|---|
| Интерфейс | Vue 3 + TypeScript, **Ionic Vue** (компоненты в стиле iOS), vue-router, Pinia |
| Сборка | Vite; тесты — vitest |
| Облако | Supabase через `@supabase/supabase-js`: вход кодом из почты, таблицы и функции из [`DATABASE.md`](DATABASE.md) |
| Хостинг | Cloudflare Pages — статический сайт, бесплатно, превью-ссылка на каждую ветку |
| iOS (этап 3) | Capacitor: `web/` → проект Xcode → TestFlight → App Store |

Сервера у веб-версии нет: браузер ходит в Supabase напрямую с публичным ключом, а доступ к данным
ограничивают правила RLS в базе (ученик видит только своё).

## Структура `web/`

```
web/
├── src/core/        ← логика тренажёра без интерфейса, порт nmt_tutor/ 1:1:
│                      config (предметы, шкалы 100–200), engine (план, проверка, баллы, отчёт),
│                      hints (10 уровней), generators/* (по предметам), cabinet (цифры кабинета)
├── src/core/data/   ← задания и шкалы (JSON, перенесены из nmt_tutor/ один раз)
├── src/cloud/       ← вход, профиль, begin_session / submit_session, история, серия дней
├── src/stores/      ← Pinia: app (аккаунт, профиль, история, серия), training (идущая тренировка, чат Совы)
├── src/views/       ← экраны: вход, профиль, кабинет, выбор предметов, шкала 100–200, тренировка
│                      (с похожим примером), итоги, «Про програму»
├── src/components/  ← Сова, поле ответа (5 типов заданий), шкала подсказок, чат, график, карточка предмета
└── tests/           ← vitest: паритет с Python на эталонах + генераторы, сборка теста, облако
```

## Данные и паритет с Python

`tools/export_web_data.py` (запускается из корня репо системным `python3`) один раз переносит в `web/`:
- `src/core/data/subjects.json` — предметы, число заданий, пороги, шкалы 100–200, список генераторов;
- `src/core/data/bank.json` — встроенный банк заданий;
- `src/core/data/language_cases.json` — таблицы языковых генераторов;
- `tests/fixtures/*.json` — эталонные ответы Python: проверка 987 ответов, шкалы, 10 подсказок для каждого
  задания банка, итоги по предмету, цифры кабинета.

`tests/parity.test.ts` требует совпадения с эталонами символ в символ (округление, тексты подсказок).
`tests/core.test.ts` прогоняет каждый из 40 генераторов 200 раз: правильный ответ засчитывается,
неправильные — нет, варианты не повторяются. Сами генераторы на вебе дают другие случайные числа,
чем Python, — сравнивается поведение, а не конкретные задания.

## Облако

`src/cloud/api.ts` повторяет `nmt_tutor/cloud/sync.py`:
- вход `signInWithOtp` → `verifyOtp` (код из письма); сессию хранит supabase-js в браузере;
- профиль — строка `profiles` своего аккаунта (самая старая, как на десктопе); нет строки → форма профиля;
- тренировка начинается только после `begin_session` (без интернета не стартует);
- в конце `submit_session` с тем же payload, что у десктопа. Если сеть пропала — тренировка ждёт
  в `localStorage` (`nmt-sova-outbox`) и уходит при следующем открытии кабинета;
- история — `sessions` + `session_subjects` + неверные `session_answers` → те же записи, что читает кабинет;
- серия 🔥 — `profile_meta.data.streak`; «Видалити дані з хмари» — `delete_my_account`.

## Закрытый доступ (логин и пароль)

Пока веб открыт только для тестировщиков, перед всеми экранами (и перед входом по почте) стоит
экран «Вхід для тестувальників» — как Interceptor в Grails: охранник в `src/router.ts` не пускает
никуда, кроме `/access`, пока логин и пароль не приняты.

- Логины лежат в Supabase, таблица `app_gate_logins` (миграция
  [`20261120000000_access_gate.sql`](../supabase/migrations/20261120000000_access_gate.sql)).
  Пароли — только bcrypt-хеши; сравнивает их сама база в функции `gate_sign_in`, браузер хешей не видит.
- Правильная пара → база выдаёт токен устройства, браузер хранит его в `localStorage` (`nmt-sova-gate`)
  и при каждом запуске проверяет через `gate_check`. Логин выключен → все его устройства снова видят
  экран входа. Без интернета сохранённый токен пускает (тренировки всё равно требуют сеть).
- 10 неверных паролей к одному логину за 15 минут — вход по нему блокируется на 15 минут.
- Выход из аккаунта (почта) токен устройства не стирает.
- Локально выключить: `VITE_ACCESS_GATE=off npm run dev`.

Это защита интерфейса, а не данных: код сайта всё равно скачивается, и знающий человек может обойти
экран. Чужие данные защищает RLS в базе, как и раньше.

Управление (Supabase → SQL Editor):
```sql
select public.set_gate_login('tester', 'длинный-пароль', 'Аня, 11 клас');  -- добавить / сменить пароль
update public.app_gate_logins set enabled = false where login = 'tester';  -- выключить
select login, enabled, note, created_at from public.app_gate_logins;       -- кто имеет доступ
```

## Чем отличается от десктопа

- Только со входом в облако: одна почта = один профиль. Нет локальных профилей и PIN.
- Нет своих банков заданий, ярлыка Windows, локальной зашифрованной базы.
- Вместо «Вийти з програми» — «Вийти з акаунта».
- Профиль, созданный на компьютере, открывается в вебе со всей историей (облако общее).
- Отчёт открывается из любой тренировки в истории: он собирается из итогов в облаке, а не хранится файлом.
- Под заданием — номера всех задач блока для быстрого перехода; похожий пример без отдельного окна.
- На телефоне одна колонка, после подсказки или проверки экран сам прокручивается к Сове;
  от 900 px задание и Сова стоят рядом.
- Генератор «подвоєння» (`ukrmova_double`, `ukrmova_myak`, `ukrmova_pref_zs`) не повторяет варианты
  ответа — на десктопе изредка выпадали два одинаковых варианта.

## Десктоп заморожен

`nmt_tutor/` (Python + Tkinter) больше не получает новых функций. Он остаётся эталоном: тесты веба
сверяют ответы TypeScript-логики с Python на одних и тех же заданиях. Когда веб покроет всё, десктоп
уйдёт в архивную ветку (ROADMAP, этап 8).

## Запуск и тесты

Нужен Node.js 22 (`node -v`).

```bash
cd web
npm install          # один раз
npm run dev          # http://localhost:5173 — открывается и с телефона в той же сети: npm run dev -- --host
npm test             # vitest
npm run build        # проверка типов + сборка в web/dist
```

CI: `.github/workflows/web.yml` на каждый пуш в `web/` запускает `npm ci`, тесты и сборку.

Адрес Supabase и публичный ключ лежат в `web/src/config.ts` (те же, что в `nmt_tutor/cloud_config.json`);
их можно переопределить переменными `VITE_SUPABASE_URL` и `VITE_SUPABASE_KEY`.
`VITE_ACCESS_GATE=off` выключает закрытый доступ.

## Деплой на Cloudflare Pages (один раз)

1. Зарегистрируйся на https://dash.cloudflare.com (бесплатно).
2. **Workers & Pages → Create → Pages → Connect to Git** → GitHub → репозиторий `AlDroid007/NMT_Ow`.
3. Настройки сборки:

   | Поле | Значение |
   |---|---|
   | Project name | `nmt-sova` (будет адрес `nmt-sova.pages.dev`) |
   | Production branch | `main` |
   | Framework preset | `Vue` (или None) |
   | Root directory | `web` |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Environment variable | `NODE_VERSION` = `22` |

4. **Save and Deploy.** Дальше Cloudflare сам собирает сайт при каждом пуше:
   - `main` → основной адрес `https://nmt-sova.pages.dev`;
   - любая другая ветка → превью `https://<ветка>.nmt-sova.pages.dev` (например, `feature-web-app.nmt-sova.pages.dev`) —
     так проверяем работу до мержа, в том числе на iPhone.
5. Свой домен — позже: **Custom domains** в проекте Pages.

Неизвестные адреса (например, `/cabinet` при обновлении страницы) Cloudflare отдаёт как `index.html`
(режим SPA), поэтому роутер работает без дополнительных настроек.

### Supabase для веба
- **Authentication → URL Configuration → Site URL**: `https://nmt-sova.pages.dev`. Вход по 6-значному коду
  не использует ссылки-редиректы, но Site URL лучше выставить.
- CORS настраивать не нужно: Supabase принимает запросы с любого сайта, доступ решают правила RLS.
